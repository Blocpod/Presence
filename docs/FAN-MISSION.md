# MISSION: BUILD THE FAN EXPERIENCE FOR PRESENCE

You are GPT-6 Astra continuing development inside:

https://github.com/Blocpod/Presence

The existing creator-side PRESENCE application is already built and working.

Your mission now is to design and build the complete **fan-facing experience** for PRESENCE inside the same repository.

Do not replace the existing creator dashboard.

Extend the product with a second major experience surface:

# FAN PRESENCE

This must be the emotionally compelling side of the platform.

The creator dashboard proves control.

The fan experience must prove desire.

The fan should immediately understand why someone would want to pay for access to an AI version of a creator they follow.

---

# 1. CORE OBJECTIVE

Build the strongest possible fan experience demonstration for PRESENCE.

This should NOT feel like:

* a SaaS dashboard,
* a chatbot app,
* a CRM,
* a generic AI companion,
* a Discord clone,
* an OnlyFans clone,
* or a technical demo.

It should feel like:

# A PRIVATE DIGITAL PRESENCE

The experience should communicate:

> This creator is here with me.

Even though the current demo is not yet using a true photoreal realtime digital human.

The product must still make the underlying future obvious.

---

# 2. DESIGN STANDARD

This must be AAA.

Target quality:

* Awwwards-level
* FWA-level
* Apple product-launch quality
* cinematic
* editorial
* luxurious
* emotionally immersive
* highly intentional
* visually original
* mobile-first
* motion-led
* memorable enough to become the visual identity of the product

Do not settle for "polished startup UI."

That is not enough.

The standard is:

> Could this interface win digital design awards even if the viewer knew nothing about the technology?

If not, keep iterating.

---

The fan side should feel closer to:

* FaceTime from the future

NOT:

* cyberpunk
* neon hacker UI

* generic glassmorphism
* excessive gradients
* gaming HUDs
* AI robot motifs

* conventional sidebars
* card-grid dashboards

The software should almost disappear around the creator.

The creator is the interface.

---

# 4. PRODUCT PRINCIPLE

The creator-side experience is:

CONTROL.

The fan-side experience is:

PRESENCE.

These must feel deliberately different while belonging to the same brand.

Creator Studio:
precise, intelligent, controlled, operational.

Fan Presence:
emotional, cinematic, immersive, intimate, alive.

---

# 5. MOBILE FIRST

Design the fan experience primarily around the phone.

The first target viewport is a modern mobile device.

The experience should feel exceptional at approximately:

390 × 844

and scale beautifully upward.

Desktop should remain excellent, but mobile is the emotional core.

Avoid simply shrinking desktop layouts.

Restage the composition intentionally.

Build one exceptionally strong complete journey.

# 7. THE MAIN PRESENCE SCREEN

This is the most important screen in the entire fan product.

Design it as an immersive creator surface.

The creator image or visual representation should occupy most of the visual hierarchy.

Use the existing fictional creator Mira Vale.

You may create or select appropriate fictional demo imagery if required, but do not use unauthorized real-person likenesses.

The current product does not have a photoreal realtime digital human.

Do not fake one.

Instead, make the experience highly convincing using:

* high-quality still creator imagery
* subtle parallax
* depth effects
* lighting movement
* breathing-scale motion
* responsive image treatment
* atmospheric animation
* controlled camera movement
* layered depth
* restrained particles if genuinely useful
* blur and focus transitions
* visual reactions during voice activity

The fan should understand:

"This is the visual representation of Mira's Presence."

---

# 8. COMMUNICATION SHOULD NOT LOOK LIKE CHATGPT

Avoid making text conversation the dominant visual metaphor.

Conversation may exist, but it should feel integrated into the Presence.

Potential interaction language:

* contextual text appearing near the creator
* elegant transcript overlays
* voice-first interaction
* minimal temporary speech surfaces
* fading conversational fragments
* responsive subtitles
* spatial text placement

Avoid large stacks of rounded chat bubbles.

If chat bubbles are used, they must be visually subordinate.

---

# 9. VOICE-FIRST EXPERIENCE

Make voice feel like the premium default interaction mode even if the actual demo still uses browser speech capabilities.

The existing voice implementation may be used or improved.

Create a voice interaction state that feels alive.

Potential visual cues:

* subtle waveform
* creator glow/reaction
* ambient motion
* listening indicator
* speaking indicator
* interrupt state
* microphone state
* connection state

Do not use generic "recording" UI if a more elegant interaction is possible.

The voice experience should feel conversational rather than command-driven.

---

# 10. RELATIONSHIP MEMORY

The relationship engine is one of PRESENCE's biggest strategic assets.

Make the fan feel it.

Do NOT present memory as a database.

Do NOT create a "Memories" dashboard unless useful as a secondary optional view.

Instead, reveal memory context naturally.

Example:

Mira says:

> You were still deciding between the Ducati and Triumph last time. Did you ever pick one?

The UI could subtly surface:

REMEMBERED FROM YOUR LAST CONVERSATION

or something more elegant.

The relationship should visibly deepen over time.

Potential relationship cues:

* relationship duration
* recurring interests
* shared moments
* remembered milestones
* subtle continuity indicators
* "Mira remembered..."
* evolving interaction context

Keep it human and emotional.

Do not make it creepy.

---

# 11. SURFACE MODES

The fan should be able to move between richer forms of Presence.

At minimum support visible modes such as:

TEXT

VOICE

VISUAL

SPATIAL

But do not present these as ugly tabs unless the design demands it.

Design a beautiful mode switcher.

The underlying creator identity and fan relationship must remain the same across every mode.

This continuity is critical.

---

# 12. VISUAL MODE

Visual mode should feel like a premium private session.

The fan should see Mira prominently.

Use advanced image presentation to simulate greater dimensionality without pretending the system is live video.

Clearly indicate that the current demo is a visual Presence representation.

Potential treatment:

* fullscreen image
* depth mapping/parallax if reasonable
* soft camera drift
* simulated focal changes
* responsive lighting
* subtle gaze illusion where ethically and technically appropriate
* motion-reactive overlays
* dynamic crop/framing

Prioritize taste.

Avoid gimmicks.

---

# 13. SPATIAL / AR / VR PREVIEW

Do NOT pretend we have solved realtime photoreal AR/VR.

Build a beautiful and truthful spatial preview.

Call it something like:

# SPATIAL PRESENCE

or

# PRESENCE IN YOUR SPACE

The demo should make the future obvious.

Use the existing WebGL/WebXR architecture where useful.

Potential experience:

* fan enters a spatial preview
* Mira appears represented within a designed room or real-world-inspired spatial composition
* interface explains that production deployments could render the same governed Presence through AR/VR hardware
* creator identity, memory and permissions remain continuous

Make this visually spectacular.

The current limitation should be presented elegantly, not apologetically.

Example:

> Spatial Presence Preview
> This demo uses a visual representation. The same identity runtime is designed to connect to realtime avatar and AR/VR renderers.

Do not bury the disclosure.

Do not let disclosure destroy the experience.
