# Executive demonstration

Allow approximately six minutes. Use only the fictional demo identities. Start the application with the README instructions, load the seeded environment, and check current limitations in STATE.md. The route and exact controls may evolve; the steps below describe the acceptance story rather than undocumented API calls.

**Opening:** “Mira Vale is a fictional 28-year-old creator. This is a local AI-presence sandbox. Every financial number is simulated or projected. The voice is a generic browser voice, and no real person has joined.”

## 1. Authorization and creator control — 45 seconds

Open the creator view. Inspect Mira's structured identity and permitted uses. Point out fictional authorization status, required AI disclosure and revocation. Show facts, conversational style and boundaries as separate concerns. Explain that a real pilot would consume verified identity and signed licensing from approved systems.

**Evidence:** The identity and its governing configuration are inspectable. Do not describe a simulated approval as real verification.

## 2. One identity, distinct relationships — 75 seconds

Open a fan session and acknowledge the adult-demo/disclosure step. Ask about one of the creator's approved interests: travel, music or photography. Save a harmless preference using the available memory control, then reload and inspect it. Switch to another fictional fan and show that the first fan's new preference is absent.

Use two tabs or windows to contrast fan views if supported. This demonstrates separate relationships; it is not a load test or proof of unlimited concurrency.

**Evidence:** Persistent pair-specific state, provenance and visible AI status. Delete the new memory and confirm it disappears.

## 3. Richer presence — 45 seconds

Try the voice surface if speech is supported, then show the visual/spatial scene. State that the same identity and permissions govern each renderer. Describe the scene as a spatial prototype. If audio or WebGL is unavailable, show the fallback and continue the text interaction. Do not imply a photorealistic live stream or tested headset session.

## 4. Governance that changes the interaction — 60 seconds

Return to creator controls, change a supported permission and save. Repeat the affected fan interaction. Inspect the refusal/disabled state and the relevant audit or policy explanation. Demonstrate that changing the setting changes behavior, rather than only changing a badge.

Simulate creator takeover using the session control. Point out the simulated human state and blocked AI input; return control to AI. No actual Mira exists or joins this demonstration.

## 5. Metered activity and potential economics — 60 seconds

Open the sandbox usage/analytics view. Identify events generated by the session and distinguish them from seeded example activity. Open the economic model and adjust one assumption. Explain gross creator/platform shares and the fact that provider, support and payment costs must be measured before profit can be estimated.

**Suggested narration:** “The integration asset is an authorized usage event the incumbent can reconcile with its own entitlements and payments. These totals are not earned revenue.”

## 6. Creator revocation — 45 seconds

Disable or revoke Mira's Presence. Attempt another fan interaction and show it is blocked. Inspect the state/audit record. Finish by showing the roadmap's provider and production dependencies.

**Closing:** “The prototype makes the governance chain reviewable. The next proof is a consented partner pilot measuring usefulness, creator effort, trust and fully loaded economics.”

## Recovery and demo hygiene

If the database has earlier demo activity, explain it or reset only through the documented local reset procedure. Never delete external data. Re-enable the fictional identity through the supported control before rehearsing again. Do not invent passing results if a step fails; record the failure and use EVALS.md as the source of tested status. Do not enter real fan data, real license documents or payment details.
